### Behaviour delivered

- `Settings` carries `playback_info_response_fields` and
  `playback_info_media_source_fields` (both empty from `from_env()` and when the
  TOML `playback_info` table or either sub-table is missing/empty).
  `Settings.from_file()` validates and copies both tables; `from_env()` invents no
  new variables.
- Startup validation rejects non-table `playback_info`, non-table sub-tables, empty
  field names, `response_fields.MediaSources`, TOML date/time values and
  NaN/Infinity (recursively through arrays/objects), reporting only the dotted
  location and the offending type.
- `PlaybackService.modify()` applies explicit root fields first, then the existing
  media source policy extension point, then the explicit media source fields as
  the final values, and only then records the resulting `Id`/`Path`. Empty
  collections keep every field untouched. Configured arrays/objects are deep
  copied per media source so neither the configuration nor other responses are
  shared or mutated.
- `main.create_app()` no longer assembles `ProtocolFileRule()`. The rule class and
  the `MediaSourceRule` extension point are unchanged, and an explicitly
  configured rule still runs before the configured field values win.
- `MediaSourceCache.forget()` removes exactly one normalized `MediaSourceId`; when
  an override changes `Id`, the old mapping is dropped and the final `Id`/`Path`
  feeds the Video 302. An overridden invalid `Path` clears only that ID. Capacity,
  LRU and the rest of the invalidation semantics are untouched.
- Bypass (`modify=False`) returns the upstream bytes verbatim, applies no field
  override, and still seeds the real upstream mapping.
- `JellyfinProxy.toml`, README and CHANGELOG describe the two tables, the
  no-override default, the explicit opt-in that restores `Protocol="File"` /
  `SupportsTranscoding=false`, and the restart-to-apply behaviour. `version.py`
  stays 0.9.3.

### Decisions / Risks / Remaining Outcomes

- Scope decision: the override applies to a source whose Path is a usable HTTP(S)
  URL at the point the field table is written, i.e. after the policy stage. The
  practical difference from the pre-policy Path only appears if a custom rule itself
  rewrites a Path into/out of HTTP(S); with the shipped (empty) rule list both
  readings are identical, and documents from Jellyfin already carry the real Path.
  B may re-read AC-3/AC-5 here.
- An override that sets `Path` to `null` is impossible by design (TOML has no null
  and null sentinels are a non-goal); clearing a field therefore needs a subsequent
  Jellyfin response, exactly as before.
- Default-behaviour change is user-authorized: an existing deployment without the
  new tables now receives Jellyfin's `Protocol` / `SupportsTranscoding` values.
  Documented in README and CHANGELOG; no `version.py` bump in this Task.
- `response_fields.MediaSources` is rejected rather than ignored, which is a startup
  error for a configuration that would silently do nothing.
- Overriding `Id` to an already-known different ID follows the existing
  `remember()` rules (last write wins for that ID); no additional cleanup was added.
- Unchanged by design: cache removal, bypass precedence, routes, error semantics,
  streaming/Range, `MediaSourceCache` capacity/LRU, `scripts/validation/` (it still
  writes legacy cache keys and is not part of this Task's inputs).
- NOT RUN: real Jellyfin 12.3 (RO-7 / RJ-03 / RJ-11 / RJ-12 candidate configs),
