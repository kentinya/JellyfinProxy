## 实际缺口与范围

已核对 README、当前合同 / 状态文件及以下真实实现、配置行为说明和测试：

- `routers/route_config.py` 的 video 规则未限制方法，且接受任意 `/Videos/{id}/...`、
  `/videos/{id}/...` 和 `/video/...`；`Router.match()` 已用 fullmatch，可沿用现有结构。
- `VideoHandler.handle()` 未判断 HEAD；两种查询 ID 和路径 ID 最终共用映射查找，
  命中即返回 302。应在查询映射前分出 HEAD，不改 GET 的 ID 选择和映射算法。
- `Dispatcher.dispatch()` 提前处理绕过；现有 `client_identified` 的 `modify` 不能说明
  实际视频处理，通用 `request_completed` 记录方法、路径、状态和耗时，但没有映射结果。
- `ProxyHandler` 已采用 StreamingResponse 并关闭上游响应，`JellyfinHttpClient`
  已保留原方法 / 原始路径 / 查询并禁止跟随重定向，默认优先复用。
- `tests/test_core.py` 已有 `_app_with_scripted_upstream`、`_seed_media_mapping`、
  可观察关闭状态的流及 GET 映射 / 策略回归；旧路由测试仍认定 master / HLS 和 `/video`
  属于 VIDEO，应改为实际透传断言，不是简单删除测试。
- `tests/test_logging.py` 已有请求 ID、脱敏和 PlaybackInfo 日志检查；`docs/configuration.md`
  仍描述旧视频路由。已查阅的验证脚本视频入口为合法 stream 格式，无需借此改造历史工具。
- 规划开始时跟踪文件无未提交修改，只有未跟踪 `artifacts/`；保留，不暂存或清理。

以上为源码核对，不冒充已运行的缺陷复现或产品测试结果。

   自然落到 DEFAULT；`Videos` / `stream` 大小写不敏感，不改 PlaybackInfo 路由。
2. 在 `handlers/video_handler.py` 增加 HEAD 直接代理；GET 沿用现有 ID 选择、UUID
   规范化、映射命中跳转 / 未命中回退，不修改媒体源缓存或客户端策略算法。

   或固定字段格式，也不要求新增上下文对象或改造所有请求的异常机制。

   及直接相关 HTTP 适配做最小修正；说明原因并按下方条件补测，不借机重构整个代理。
