## 配置界面

在 `JellyfinProxy.toml` 末尾使用两个可选表：

```toml
# 可选：覆盖 PlaybackInfo 响应根对象的直接字段，默认不修改根字段。
[playback_info.response_fields]

# 可选：覆盖每个可用 HTTP(S) 媒体源的直接字段。
[playback_info.media_source_fields]
Protocol = "File"
SupportsTranscoding = false
SupportsDirectPlay = true
```

以上三项均为用户主动启用修改的示例，不是默认值。模板须解释 TOML 表的作用域，
将新表放到现有根配置之后，避免其后的 `listen_port` 等原根字段意外归入新表。

| 项目 | 精确语义 |
|---|---|
| `playback_info` 缺省 | 两个字段集合均为空；保留 Jellyfin 返回的全部字段值，不执行隐式覆盖 |
| `response_fields` 缺省或空表 | 不配置根字段覆盖 |
| `media_source_fields` 缺省或空表 | 不修改媒体源字段；直链记录和 Video 逻辑继续运行 |
| 显式提供非空字段表 | 仅修改该表列出的字段，不补充任何未配置的隐式修改 |
| 重复字段 / 非法 TOML | 按现有配置错误处理，不按最后一项悄悄覆盖 |
| 配置生效时机 | 启动加载，修改后重启；本次不引入热更新或新的环境变量编码协议 |

因此只配置 `SupportsDirectPlay=true` 就只修改这一项；缺省表与显式空表在字段修改上等价。
`Settings.from_env()` 无文件场景同样使用空字段集合，其他已有环境变量覆盖规则不变。
原先自动写入 `Protocol="File"`、`SupportsTranscoding=false` 的行为取消；需要恢复该效果的用户
可以显式配置这两项。这是用户本轮授权的默认行为变化，升级说明与真实服务差异核对须如实记录。
默认“不改”指 JSON 字段值不变，正文重新序列化的格式不构成字段变化；绕过客户端仍有原文返回合同。

## 字段范围与值

- `response_fields` 对应 PlaybackInfo 响应根对象的直接字段；`media_source_fields` 对应
  `MediaSources` 列表中各对象的直接字段，不作用于 `MediaStreams[]` 等嵌套对象。
- 字段名与 Jellyfin JSON 一致、区分大小写，必须是非空字符串；此版不解析点路径、数组下标、
  通配符或表达式。字段名含点且正确加引号时仍是一个字面量字段名，不是深层路径。
- 值支持 JSON 可表达的字符串、布尔、整数、有限小数、数组及对象。数组 / 对象作为整个字段值
  替换，不深层合并。TOML 没有 null，本版不引入 null 哨兵、字段删除或动态模板求值。
- 目标对象已有该字段时覆盖；缺少该字段时补入。非目标字段不变。配置本身不提供完整 Jellyfin
  Schema 校验；用户填写的值按配置原类型写入，不按字段名自动把字符串 `"false"` 转为布尔。
- `response_fields` 不得覆盖 `MediaSources` 容器；媒体源修改统一通过 `media_source_fields`，
  避免两个作用域对同一媒体源列表产生冲突。需要修改某个数组 / 对象字段时仍可替换该字段整体。
- 非对象根正文不转换为对象，沿用原行为；无 `MediaSources` 或其类型不正确时不创建列表。
  列表中的非对象项跳过；根字段仍可修改合法根对象。媒体源字段覆盖只作用于进入既有策略流程的
  可用 HTTP(S) 媒体源，本地路径、缺 Path 等媒体源继续按既有逻辑透传 / 清理直链。

## 执行顺序与直链一致性

1. 每次 PlaybackInfo 仍实时请求 Jellyfin，不为字段修改重新引入完整 JSON 缓存。
2. 非成功或不可解析的 JSON 走现有返回流程，配置不把错误响应转换成成功响应。
3. 全局 / PlaybackInfo 绕过优先：不执行根字段或媒体源字段覆盖，仍记录上游实际直链并原文返回。
4. `modify=True` 且根是对象时先应用显式配置的根字段，随后处理各媒体源；空集合不改字段。
   保留服务层策略扩展点，但应用不能默认装配会修改字段的隐式规则。
5. 对可用 HTTP(S) 媒体源应用显式配置的媒体源字段集合，配置覆盖是该阶段最终字段值。
   移除固定 `ProtocolFileRule` 的默认装配，不再自动注入旧两项值，也不能重新覆盖用户值。
6. 直链映射使用最终返回的媒体源 `Id` / `Path`，而不是覆盖前的值。配置改变 `Id` 时清理该媒体源
   原 ID 的旧映射，再按最终合法 ID 建立映射；最终 Path 无效时清理对应旧映射。其他 ID 不受影响。
   配置覆盖 `Path` 的行为仅来自用户显式配置，不新增 URL 生成、文件读取或探测。
7. 不修改共享配置或将其可变数组 / 对象直接挂进多个请求：为响应复制需要写入的值，避免响应处理
   反向污染配置或后续请求。并发请求和不同媒体源之间也不得共享可变覆盖值。

其中可用 HTTP(S) 的目标选择依据进入覆盖阶段前的 Path，沿用现有 MediaResolver 判定。
该阶段不会将本地媒体通过配置自动升级为远程媒体；若配置把远程 Path 改为不可用值，仍按原直链
缓存规则精确失效。保持既有解析异常边界，不借本功能吞掉所有畸形 URL 异常。

## 启动校验与架构边界

`playback_info` 和两个字段配置区存在时必须为表。错误的容器类型、空字段名、
`response_fields.MediaSources`、TOML 日期 / 时间类型、NaN / Infinity 等不能表示为标准 JSON
的值，均在启动加载阶段报清楚的配置错误；递归校验数组 / 对象，不能等播放请求触发序列化失败。
错误只报告配置位置和类型，不打印配置值。一般 JSON 字段值按上述原类型语义处理。

配置解析 / 默认值 / 值校验在 `config.py`，装配在 `main.py`。字段应用及与媒体规则 / 直链映射
的顺序在 `services/`；`handlers/` 只负责 HTTP 处理、修改绕过及响应适配，不承担通用字段规则。
可演进现有字段规则或增加小型服务组件，由 B 按实际实现确定；不能仅在入口硬编码示例中的字段。
测试中的其他 MediaSourceRule 扩展行为也须保持，避免删除默认硬编码时破坏整个策略扩展点。

实施时在 `JellyfinProxy.toml` / README 中提供完整样例、缺省 / 空表语义与作用域说明；
默认示例不得激活任何字段覆盖；两项旧规则和其他定制值只作为注释示例，用户主动取消注释才启用。
应用日志只记录应用计数和必要字段位置，不能输出用户配置的
正文值、认证值或完整播放 URL。原有客户端识别 / 请求 ID / 访问日志规则继续生效。
