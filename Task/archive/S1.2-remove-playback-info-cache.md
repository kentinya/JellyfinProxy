## 真实代码、缺口与范围

已阅读 PlaybackHandler / Dispatcher / main、Settings、ClientPolicy、PlaybackInfoCache、
PlaybackService / MediaSourceCache、VideoHandler、ProxyHandler / JellyfinHttpClient、现有路由、
tests/test_core.py、test_config.py、test_logging.py、test_version.py、配置样例与版本文档。

- `PlaybackHandler.handle()` 目前先按 Item 键读缓存，命中时不回源；成功 JSON 在修改前
  写缓存，所有成功 JSON 路径均生成 HIT/MISS。删除模块、键算法、读写、参数和缓存分支。
  成功 / 错误 / JSON 解析及 HTTP 头适配继续沿用已有路径，不新增成功回退或错误转换。
- `main.create_app()` 创建缓存，Dispatcher 传递实例并计算 cache_bypass；ClientPolicy
  有独立缓存绕过表与方法。移除这些专属装配 / 接口与 `client_identified` 的 cache 字段，
  保留全局 / Playback / Video 三表与优先级、身份头清洗和其余日志。
- `Settings.from_env()`、`from_file()` 及模块级 `settings` 都读取旧键。删除四项配置属性、
  默认值及读取 / 转换，保证旧 TOML 键与对应环境变量即使值不合旧类型也不生效、不报错。
- 绕过 PlaybackInfo 修改仍须经过 PlaybackHandler，每次回源并调用
  `remember_media_sources()`，原文字节返回；不能直接跳到通用代理而丢失直链填充。
- `services/media_source_cache.py` 是 Video 所需的另一套映射，不删除、不清空，不调整认证
  边界、容量或 LRU。路由、VideoHandler、流式与上游 HTTP 原则上无需修改。
- 允许修改上述缓存接入文件、删除 `services/playback_info_cache.py`、调整受影响测试、
  `.env.example`、README、适用 AGENTS / CHANGELOG；TOML 样例本来无旧缓存项，仅按实际需要改。
  删除只服务 JSON 缓存的测试维度，保留 BUG-001 每个清理 / 回退 / 恢复业务断言。
- `scripts/validation/` 是固定旧 Base 的对照工具，其缓存引用仍有用途，保留；不以全仓
  无 cache 字符串为验收，不改原证据、观测器或建库框架。启动时已有未跟踪 artifacts/ 保留。

### Decisions / Risks / Remaining Outcomes

- `PlaybackHandler.handle()` is now `(request, *, modify=True)`; `use_cache` is gone.
  No product caller remains, but any external caller of this internal handler must
  adapt.
- Legacy keys are ignored, not rejected: a user who relied on the cache now sees
  per-request latency and previously hidden upstream errors. That is the intended
  outcome and is documented.
- `scripts/validation/` intentionally still emits the removed settings (fixed-Base
  comparison tool); it was neither modified nor re-run. A full-repo absence of cache
  strings is therefore not an acceptance criterion for B.
- The old two-field modification (`ProtocolFileRule`) is still assembled by default in
  `main.create_app()`; removing that default and adding field configuration is S1.3.
- NOT RUN here: real Jellyfin 12.3 (RO-7, S1.4), real clients, packaging / binary
  build (no deployment input changed), and the `scripts/validation` tooling.
- Remaining outcomes: RO-7, RO-8 (version and release documentation hand-over), RO-9
  (field configuration) and the final C comparison belong to later Tasks.
