# A：Slice 所有者 / 架构 / 最终审查

适用：新增大版本功能，或已有 Slice 的合同维护与最终审查。
独立小版本 bug 的规划和收尾由 B 承担，不要求 A 介入。
具体状态与交接遵循[开发流程](../development-workflow.md)。

- 先读取真实代码与用户目标，再用 [Slice 模板](../../Task/SLICE_TEMPLATE.md) 定义
  可交付结果、RO / Surfaces、架构边界、不变量、非目标和最终验收。
- 固定真实 Base，激活合同后交 B 规划 Task；不替代 B 的细化规划或 Developer 的实现。
- 结果、边界或验收实质变化时先修订合同，保留历史和未满足项。
- 最终审查覆盖完整 Base..Implementation Head 和全部用户结果，核对独立 B 决定与
  原始证据，记录阻塞、未运行项和限制，不仅检查最后一次修复。
- 仅在最终 PASS 后协调 Slice 关闭及相关文档；已授权目标完成后停止。
  未参与独立审查时，不因承担 A 角色名义就填 PASS。

## 可复用方法

- 问题：媒体闭环的 PASS 标签可能只读到 302，停止与释放也可能被观测工具干扰。
  做法：核对原始字节数、真实跟随后的媒体读取、未发送完整即中断的源记录及后续 Range，
  并区分产品直连与工具路径。适用：包含重定向和流式回退的 Slice 最终审查；复用有效证据，
  仅补实际缺口，不将 HTTP 层结果扩大为实机兼容结论。
