# Developer：实施

在大版本功能与独立小版本 bug 两条路径中，Developer 的职责保持一致。
边界见 [AGENTS](../../AGENTS.md)，执行与交接见[开发流程](../development-workflow.md)。

- 开工前核对根 TASK、真实基线、B 计划检查点、工作区修改和适用合同；有 Slice
  才读取对应 ACTIVE 合同，独立 bug 以 B 的完整 Task 计划为范围依据。
- 在活动范围内实现、修复、验证和建立普通本地检查点；沿用已有结构，保持业务
  与基础设施职责清楚，不自行增添合同外能力。
- 按计划先验证新增 / 失败 / 直接影响，再完成最终候选门槛。保留真实命令、输入、
  首次失败与重跑；不能通过删除测试或弱化断言获得通过。
- 提交完成报告，说明实际行为、变更文件、实现 Head、验收映射、原始证据、剩余
  风险和未运行项，将 Task 交为 READY FOR B REVIEW。
- B 退回后在原 Task 内追加修正；不改写已审历史，不把自检称为独立 B 或 A PASS。
- 保留用户文件，不自动推送或发布；无真实 SHA 或无法执行的验证如实记录。

职责不包含代替 A / B 擅自改合同、放宽验收或签发最终审查结论。
